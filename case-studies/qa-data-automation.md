# 상담품질(QA) 평가 데이터 취합 자동화

PySide6 기반 Windows 데스크톱 RPA. CS 상담품질 평가 데이터를 자동 취합해 상담원별 개인 문서에 적재합니다.

## 배경 / 문제

- 매월 여러 개의 평가 원본 파일(상담 채널·유형별)이 Google Drive에 쌓이는 구조였습니다.
- 담당자가 이 파일들을 열어 상담원별로 데이터를 분류하고, 각자의 개인 평가 문서에 **서식까지 맞춰 수기로 옮겨 적는** 반복 업무가 있었습니다.
- 파일 수·상담원 수가 늘수록 시간이 급증하고, 수작업 과정에서 누락·중복·서식 오류가 발생했습니다.

## 역할

기획, 아키텍처 설계, 구현, 빌드·배포, 사용 가이드 작성까지 **단독 수행**. 기존 v1을 구조적으로 재설계한 **v2 재개발**을 주도했습니다.

## 기술 스택

`Python` · `PySide6`(GUI) · `Google Drive API` · `Google Sheets API` · `OAuth 2.0` · `PyInstaller`(EXE 패키징) · `Pyarmor`(코드 난독화)

## 핵심 구현 / 도전 과제

- **레이어드 아키텍처로 재설계** — 거대한 단일 처리 모듈을 `core`(데이터 읽기·필터·쓰기) / `services`(인증·Google API·설정) / `ui` 계층으로 분해해, 단방향 의존과 테스트 가능성을 확보했습니다.
- **값 + 서식 동시 처리** — 단순 값 복사가 아니라 원본 문서의 서식을 보존해 개인 문서에 반영해야 했고, 개인 문서당 **쓰기 호출을 1회로 묶어** API 호출량과 속도를 최적화했습니다.
- **멱등성·안정성** — 처리 이력 기반으로 재실행해도 중복 적재가 없도록 설계하고, 모든 API 호출에 **지수 백오프 재시도**와 호출 throttle을 내장해 대량 처리 중 일시적 오류에 견디도록 했습니다.
- **비개발자 배포** — Windows EXE로 패키징하고 GUI에서 경로·설정을 입력받도록 해, 현업 담당자가 바로 사용할 수 있게 했습니다. 민감 로직은 난독화해 배포했습니다.

## 성과

- 상담원별 수작업 분류·전사·서식 맞춤 작업을 제거해 **반복 업무를 자동화**했습니다.
- 처리 이력·재시도 설계로 수작업 대비 **누락/중복/서식 오류를 구조적으로 차단**했습니다.

*(민감 정보 제외: 실제 상담원 명단·평가 데이터, Google Drive 폴더/시트 ID, 사내 인증서는 모두 원본에만 존재하며 본 문서에서 제외함)*
